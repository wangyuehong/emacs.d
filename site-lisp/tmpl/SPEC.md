# tmpl SPEC

本文件是 tmpl 包的行为契约，是代码变更的权威参照。所有修改必须保证 spec、代码、测试三者一致。

只描述使用者可观测的行为；实现手段写在源码注释里。

## 术语

- 族：共享分隔符与结构规则的一组模板语言。包括 jinja 族与 go-template 族。
- 引擎：属于某个族的具体模板语言，另带自己的内置名单。包括 `django`、`jinja2`、`dbt`（jinja 族）与 `go-template`。
- 模板区间：从开分隔符到对应闭分隔符的文本，可跨行。
- 宿主 mode：文件本来的 major mode，模板区间之外的文本由它着色。
- 标记文件：自动识别所依据的文件，如 `manage.py`、`dbt_project.yml`、`go.mod`。
- 着色类别：模板区间内按语法划分的类别，每个类别有独立的 face，默认继承 Emacs 对应的标准 font-lock face，颜色随主题。
  - 分隔符、标签名、关键字、运算符
  - 过滤器、测试、函数调用、内置名
  - 属性、变量、字符串、数字、常量、注释
  - 未登记：处在标签、过滤器、测试的位置，但不在引擎名单与追加名字中的名字

## 全局约束

- 失败语义沿用 `site-lisp/CLAUDE.md` 的 fail-fast 约束。
- 各引擎的名单以官方源码或文档为准，登记处写明来源文件与版本。
- 不依赖 evil 及其插件；对 dumb-jump 只做软依赖。
- 宿主 mode 的 tree-sitter 解析不含模板区间，缩进与结构导航按这棵语法树工作；LSP 不受影响。

## US-0010：模板语法按类别着色

作为用户，我希望模板里的语法按类别着色，并能一眼看出模板区间与宿主代码的边界。

### AC-0010-0010：jinja 族的结构类别

- Given：buffer 的引擎属于 jinja 族
- When：显示该 buffer
- Then：各写法得到对应类别的 face
- Examples:

  | 写法 | 类别 |
  |---|---|
  | `{{`、`}}`、`{%-`、`-%}`、`{#`、`#}` | 分隔符 |
  | `{% for`、`{% endfor` | 标签名 |
  | `x \| upper`、`d \| date:"Y"` 中的 `upper`、`date` | 过滤器 |
  | `x is defined` 中的 `defined` | 测试 |
  | `{% my_tag`、`x \| shout`、`x is odd_ish` 中未登记的名字 | 未登记 |
  | `f(1)` 中的 `f` | 函数调用 |
  | `shop.name` 中的 `name` | 属性 |
  | `shop.name` 中的 `shop`、`{% for x in xs %}` 中的 `x`、`xs` | 变量 |
  | `==`、`~`、`\|` | 运算符 |
  | `'a'`、`"b"` | 字符串 |
  | `3`、`1.5` | 数字 |
  | `{# … #}`、`{% comment %}…{% endcomment %}` 的内部 | 注释 |

### AC-0010-0020：go-template 族的结构类别

- Given：buffer 的引擎是 `go-template`
- When：显示该 buffer
- Then：各写法得到对应类别的 face
- Examples:

  | 写法 | 类别 |
  |---|---|
  | `{{`、`}}`、`{{-`、`-}}` | 分隔符 |
  | `.Name`、`.` | 属性 |
  | `$x`、`$` | 变量 |
  | `\|`、`:=`、`=` | 运算符 |
  | `"a"`、`` `raw` `` | 字符串 |
  | `3`、`1.5` | 数字 |
  | `{{/* … */}}` 的内部 | 注释 |

### AC-0010-0030：名单中的每一项都按类别着色

- Given：buffer 的引擎为下表之一
- When：名单中的某一项出现在模板区间内它的语法位置上（标签在 `{%` 之后，过滤器在 `|` 之后，测试在 `is` 之后）
- Then：它得到该名单对应类别的 face
- Examples:

  | 引擎 | 名单 | 类别 |
  |---|---|---|
  | `jinja2` | 标签，含中间与结束标签 | 标签名 |
  | `jinja2` | 内置过滤器 | 过滤器 |
  | `jinja2` | 内置测试 | 测试 |
  | `jinja2` | 全局函数、`loop` | 内置名 |
  | `django` | 内置与标准库的标签，含中间与结束标签 | 标签名 |
  | `django` | 内置与标准库的过滤器 | 过滤器 |
  | `django` | `forloop`、`block` | 内置名 |
  | `dbt` | `jinja2` 的全部名单 | 同 `jinja2` |
  | `dbt` | 块标签 | 标签名 |
  | `dbt` | Jinja 函数与上下文变量 | 内置名 |
  | `go-template` | 动作 | 关键字 |
  | `go-template` | 预定义函数 | 内置名 |
  | 各族 | 表达式关键字 | 关键字 |
  | jinja 族 | `true`、`True`、`false`、`False`、`none`、`None` | 常量 |
  | go-template 族 | `true`、`false`、`nil` | 常量 |

### AC-0010-0040：内置名只在所属引擎下生效

- Given：模板区间内出现 `{{ ref('m') }}`
- When：显示该 buffer
- Then：引擎为 `dbt` 时 `ref` 得到内置名 face，引擎为 `django` 时得到函数调用 face

### AC-0010-0050：raw 类块内部不按模板着色

- Given：jinja 族 buffer 含 `{% raw %}…{% endraw %}` 或 `{% verbatim %}…{% endverbatim %}`
- When：显示该 buffer
- Then：块内部文本（含其中的 `{{ x }}`）不出现任何模板类别的 face

### AC-0010-0060：跨行区间整体着色，编辑后保持一致

- Given：模板区间跨越多行
- When：在区间内任意位置插入或删除文本，或拆开、合上分隔符
- Then：重新显示后，每个位置的 face 与对编辑后的全文重新着色的结果相同

### AC-0010-0070：分隔符与宿主代码外观不同

- Given：彩色显示，face 为默认配置
- When：显示含模板的 buffer
- Then：分隔符的外观与宿主的标签名、函数名、关键字都不同
- And：未登记的外观与标签名、过滤器、测试都不同，且不使用警告或错误的外观

### AC-0010-0080：按项目追加名字

- Given：通过文件局部变量或 `.dir-locals.el`，为标签、过滤器或测试追加了名字
- When：该名字出现在对应的语法位置上
- Then：它得到标签名、过滤器或测试的 face，不再是未登记

## US-0020：宿主代码不受模板干扰

作为用户，我希望模板之外的代码照常着色，模板里的引号、注释符不打乱宿主语法。

### Background

- Given：buffer 的引擎不为 nil

### AC-0020-0010：模板外的着色与宿主自身一致

- When：显示该 buffer
- Then：模板区间之外每个位置的 face，与把模板区间替换成等长占位文本后宿主 mode 自身的着色相同
- And：宿主语言名单中的每一项在模板区间外得到宿主的着色
- Examples:

  | 宿主语言 | 名单 |
  |---|---|
  | SQL | 宿主 mode 当前方言的全部关键字、类型、函数 |
  | HTML | 全部元素名、全局属性、doctype、注释 |
  | YAML | 布尔与 null 的全部写法、指令、锚点、别名、标签、文档标记、注释、键 |
  | Go | 全部关键字、内置函数、运算符、预声明类型与常量 |

### AC-0020-0020：模板内容不改变宿主的语法状态

- Given：SQL buffer 含下表中的模板区间
- When：显示该 buffer
- Then：区间之后的文本仍按区间之前的语法状态着色，不被当成字符串或注释的延续
- Examples:

  | 模板区间 | 含有的宿主语法 |
  |---|---|
  | `{# don't -- x #}` | 单引号、行注释起始符 |
  | `{{ "a/*" }}` | 块注释起始符 |
  | `'{{ 'x' }}'` | 位于宿主字符串中，内含单引号 |
  | `-- {{ a` 换行 `}}` | 起始于宿主行注释并跨行 |

### AC-0020-0030：模板区间内不出现宿主的着色

- Given：模板区间含宿主关键字或位于宿主字符串中，见下表
- When：显示该 buffer
- Then：区间内只出现模板类别的 face，未归类的文本显示为默认前景，不带宿主的关键字色或字符串色
- And：`and`、`or`、`not`、`in`、`is`、`if`、`else`、`end`、`select`、`range` 在区间外仍得到宿主的着色
- Examples:

  | 宿主 | 文本 | 区间内的词 | 类别 |
  |---|---|---|---|
  | SQL | `{{ config(bind=false) }} false` | `false` | 常量 |
  | SQL | `select {{ a and b }} and` | `and` | 关键字 |
  | SQL | `select {{ x \| select }} select` | `select` | 过滤器 |
  | HTML | `<a href="{% url 'x' %}">` | `url` | 标签名 |

## US-0030：按项目自动识别引擎

作为用户，我希望打开文件时自动判断模板引擎，标准项目不用逐个配置。

### AC-0030-0010：标准项目

- Given：文件位于某个标记文件所在目录之下
- When：打开该文件
- Then：buffer 的引擎如下表
- Examples:

  | 标记文件 | 文件 | 引擎 |
  |---|---|---|
  | 设置 `DJANGO_SETTINGS_MODULE` 的 `manage.py` | 其下 `templates` 目录内的 `.html` | `django` |
  | 同上 | 其下 `jinja2` 目录内的 `.html` | `jinja2` |
  | `dbt_project.yml` | 其下的 `.sql`、`.yml`、`.yaml` | `dbt` |
  | `go.mod` | 其下的 `.tmpl`、`.tpl`、`.gotmpl` | `go-template` |

### AC-0030-0020：多个标记文件时取最近者

- Given：文件的上级目录中有多个可匹配的标记文件
- When：打开该文件
- Then：引擎由离文件最近的标记文件决定

### AC-0030-0030：不满足条件时不启用

- When：打开下表中的文件
- Then：buffer 的引擎为 nil，行为同 AC-0060-0010
- Examples:

  | 文件 |
  |---|
  | `manage.py` 未设置 `DJANGO_SETTINGS_MODULE` 时其下 `templates` 内的 `.html` |
  | Django 项目中 `templates`、`jinja2` 之外的 `.html` |
  | 上级目录没有任何标记文件的 `.html`、`.sql` |
  | `.github/workflows` 下含 `${{ }}` 的 `.yml` |

### AC-0030-0040：与规则无关的文件不访问文件系统

- Given：文件名不匹配任何识别规则
- When：打开该文件
- Then：不为识别而查找标记文件

## US-0040：显式指定引擎

作为用户，我希望在非标准项目里自己指定引擎，或关闭某些目录的识别。

### AC-0040-0010：显式指定优先于自动识别

- Given：通过文件局部变量或 `.dir-locals.el`（可按子目录）为文件指定了已登记的引擎
- When：打开该文件
- Then：buffer 使用指定的引擎，不论标记文件如何；AC-0060-0030 的情形除外

### AC-0040-0020：显式关闭

- Given：为文件指定的引擎为 nil
- When：打开该文件
- Then：buffer 的引擎为 nil，即使标记文件匹配

### AC-0040-0030：指定未登记的引擎时报错

- Given：为文件指定了未登记的引擎名
- When：打开该文件
- Then：以 `user-error` 提示该名字，buffer 不启用模板着色

## US-0050：模板文件按内层语言选宿主

作为用户，我希望 `x.go.tmpl` 这类文件按内层语言打开，模板着色叠加其上。

### AC-0050-0010：按内层扩展名选 major mode

- Given：本包的全局模式已开启
- When：打开带模板后缀（`.tmpl`、`.tpl`、`.gotmpl`）的文件
- Then：major mode 与去掉模板后缀后的同名文件相同；去掉后仍无法确定时，与内容相同的无扩展名文件相同
- Examples:

  | 文件 | major mode 同 |
  |---|---|
  | `a.go.tmpl` | `a.go` |
  | `a.sql.tmpl` | `a.sql` |
  | `a.yaml.tmpl` | `a.yaml` |
  | `a.html.tmpl` | `a.html` |
  | 内容为 HTML 的 `a.tpl` | 内容相同的无扩展名文件 |
  | `a.body.tmpl` | 内容相同的无扩展名文件 |

### AC-0050-0020：关闭全局模式后恢复原有打开方式

- Given：本包的全局模式已开启后又关闭
- When：打开带模板后缀的文件
- Then：major mode 与从未开启本包时相同

## US-0060：非模板文件不受影响

作为用户，我希望未识别为模板的文件与不装本包时完全一样。

### AC-0060-0010：引擎为 nil 的 buffer 不被改动

- Given：buffer 的引擎为 nil
- When：打开并显示该文件
- Then：着色、语法状态与不加载本包时相同

### AC-0060-0020：不加载 evil 也可用

- Given：Emacs 未加载 evil 及其插件
- When：加载本包并打开模板文件
- Then：模板着色正常，且 evil 未被加载

### AC-0060-0030：本身支持模板的 mode 中不启用

- When：打开该文件，即使显式指定了引擎或匹配识别规则
- Then：buffer 的引擎为 nil，行为同 AC-0060-0010，由该 mode 自己负责模板着色

## US-0080：跳到模板里的定义

作为用户，我希望在模板里对 macro、block 等名字跳到定义处。

### Background

- Given：dumb-jump 已安装且已加载，作为 xref 后端

### AC-0080-0010：跳到定义

- Given：光标在下表「用处」的名字上
- When：查找定义
- Then：跳到「定义」所在的文件与行，定义可以在同类的另一个文件中
- Examples:

  | 用处 | 定义 |
  |---|---|
  | `{{ m() }}`、`{% call m() %}` | `{% macro m(` |
  | 子模板的 `{% block b %}` | 父模板的 `{% block b %}` |
  | `{{ x }}` | `{% set x = … %}`、`{% set x %}` |
  | `{{ ns.f() }}`、`{{ f() }}` | `{% import … as ns %}`、`{% from … import f %}` |
  | dbt 的 `materialized='m'`、`ref('s')` | `{% materialization m, … %}`、`{% snapshot s %}` |
  | `.sql` 中出现的测试名 `t` | `{% test t(` |
  | `{{ template "t" . }}` | `{{ define "t" }}`、`{{ block "t" . }}` |
  | `$v` | `{{ $v := … }}` |

### AC-0080-0020：没有定义时本包的规则不给出结果

- Given：光标在没有定义的名字上，该名字在项目里另有出现
- When：查找定义
- Then：本包追加的规则不给出任何结果
- And：dumb-jump 自身的同名兜底搜索照常工作，不在本包范围内

### AC-0080-0030：dumb-jump 原有跳转不变

- Given：光标在不含模板的 JS、SQL 文件里的名字上
- When：查找定义
- Then：结果与未加载本包时相同

### AC-0080-0040：未安装 dumb-jump 时无影响

- Given：dumb-jump 未安装或未加载
- When：加载本包并打开模板文件
- Then：不报错，dumb-jump 不会因本包被加载

## US-0090：输入开分隔符时补全闭分隔符

作为用户，我希望输入开分隔符时自动补上对应的闭分隔符，少敲几个字符。

### Background

- Given：buffer 的引擎不为 nil

### AC-0090-0010：补全闭分隔符

- When：在模板区间之外输入开分隔符的最后一个字符
- Then：得到下表的文本，光标位于 `|` 处
- And：与 `electric-pair-mode` 同时开启时，结果相同，不残留多余的闭合字符
- Examples:

  | 族 | 输入 | 结果 |
  |---|---|---|
  | jinja 族 | `{{` | `{{ \| }}` |
  | jinja 族 | `{%` | `{% \| %}` |
  | jinja 族 | `{#` | `{# \| #}` |
  | go-template 族 | `{{` | `{{ \| }}` |

### AC-0090-0020：模板区间内不补全

- Given：光标位于已有的模板区间内
- When：输入开分隔符
- Then：本包不额外插入字符，结果与未开启本包时相同

## US-0100：高亮配对的块标签

作为用户，我希望阅读模板时看清一个块从哪里开始、到哪里结束。

### AC-0100-0010：高亮同一块的全部标签

- Given：光标位于下表某个块的标签上
- When：光标停留
- Then：同一块的开标签、中间标签、结束标签都被高亮，外观默认与括号匹配相同
- Examples:

  | 族 | 块 |
  |---|---|
  | jinja 族 | `{% if %}`、`{% elif %}`、`{% else %}`、`{% endif %}` |
  | jinja 族 | `{% for %}`、`{% empty %}`、`{% endfor %}` |
  | jinja 族 | `{% block b %}`、`{% endblock b %}` |
  | go-template 族 | `{{ if }}`、`{{ else }}`、`{{ end }}` |
  | go-template 族 | 嵌套的 `{{ range }}`、`{{ with }}` 与各自的 `{{ end }}` |

### AC-0100-0020：离开块标签后取消高亮

- Given：配对的块标签正被高亮
- When：光标移到块标签之外
- Then：高亮消失

### AC-0100-0030：找不到配对时不高亮

- Given：光标位于没有闭合的块标签上，如缺少 `{% endif %}` 的 `{% if %}`
- When：光标停留
- Then：不高亮任何标签，也不报错

## 边界

- 闭分隔符出现在模板内的字符串里（如 `{{ "}}" }}`）时，区间在该处提前结束。
- 不支持 Jinja 的行语句（以 `#` 开头的语句行）。
- 非标准项目的识别需显式指定（US-0040）。
- 配对只高亮，不做配对跳转；不支持跨文件类型（`{% url %}` → `urls.py`）与按文件名（`ref()` → 模型文件）的跳转。
